# ตรวจตำแหน่งลายเซ็นแยกตามแบบฟอร์ม

ตรวจวันที่ 3 พฤศจิกายน 2569 จากโค้ดฐาน `main`, แพตช์หน้าวางตำแหน่งที่แยกไว้ และแบบฟอร์มในโปรเจกต์ 22 ไฟล์ รวม 38 หน้า การตรวจรอบนี้ไม่มีการแก้คำร้องหรือ deploy เพิ่ม และยังไม่ใช่การตรวจเอกสารนิสิตทุกฉบับบน PRD

## สิ่งที่ยืนยันจากแบบฟอร์ม

| แบบฟอร์ม | ความแตกต่างที่มีผลต่อการลงนาม |
| --- | --- |
| KU1 และ KU3 | ช่องอาจารย์อยู่ช่วงท้ายหน้า ตำแหน่งชื่อและวันที่ต่างกัน และมีฉบับที่เพิ่มหน้าความเห็นผู้สอน |
| คำร้องทั่วไปของคณะ | มีช่องท้ายหน้า 4 ช่อง แต่แบบกำแพงแสนมีการแบ่งคอลัมน์และเส้นทางอนุมัติอีกแบบ |
| ผ่อนผันค่าธรรมเนียม | แบบบางเขนและกำแพงแสนมีแถว/คอลัมน์ลงนามต่างกัน พิกัดจากฉบับที่แก้ก่อนหน้าใช้แทนทุกฉบับไม่ได้ |
| ลาพักการศึกษา | ช่องลงนามต่างกันตามวิทยาเขต และบางแบบมีหนังสือยินยอมผู้ปกครองในหน้าที่ 3 |
| เปลี่ยนชื่อ/นามสกุล | พบช่องนิสิตลงนาม แต่ไม่พบช่องอาจารย์/หัวหน้าภาค/คณบดีในแบบนั้น จึงไม่ควรใส่ชุดพิกัดอนุมัติทั่วไปโดยอัตโนมัติ |

ขนาดกระดาษใกล้ A4 เหมือนกันไม่ได้แปลว่าใช้ตำแหน่งลงนามเดียวกันได้ ค่าที่สกัดจากข้อความใน PDF เป็นตำแหน่งป้ายและเส้นอ้างอิง ไม่ใช่พิกัดมุมภาพลายเซ็นที่พร้อมนำไปบันทึก

## สาเหตุในโค้ด

1. `SignatureAndPlaceModal.tsx` ในฐาน main กำหนดตำแหน่งตามเลข level โดยไม่รู้ตัวแบบฟอร์ม ส่วน Smart Presets ในชุด SIT ที่ยังไม่ deploy ใช้ชื่อ/ประเภทเป็นเงื่อนไข ซึ่งยังไม่แยกรุ่นเอกสารจริง
2. `SubmitForm.tsx` สร้าง level เรียงตาม workflow ของแต่ละฟอร์ม จึงไม่สามารถสมมติว่า level 1 เป็นอาจารย์ที่ปรึกษาเสมอได้ บางฟอร์มอาจมีหัวหน้าภาคหรือคณบดีเป็นขั้นแรก
3. หน้าของอาจารย์ให้เลือกไฟล์ PDF จากรายการแนบ แต่ข้อมูลขั้นอนุมัติบันทึกเพียงพิกัดและเลขหน้า ไม่มีตัวระบุไฟล์ที่ใช้วาง ขณะที่หน้าปรับของ Admin และจุดสร้างเอกสารหลายแห่งเลือกไฟล์แนบแรก จึงเสี่ยงวางบนไฟล์หนึ่งแต่ประทับบนอีกไฟล์
4. การตั้งหน้าสำหรับขั้น 3 ขึ้นไปถูก effect รีเซ็ตกลับหน้า 1 ตอนเปิด component จึงไม่ใช่การเลือกหน้าตามแบบฟอร์มที่แน่นอน
5. การคัดลอกไปคำร้องอื่นอาศัย `form_type` แต่ไม่ยืนยันว่าไฟล์แนบมีโครงสร้างเดียวกัน อีกทั้งคัดลอกค่าข้อความ/วันที่บางส่วนและไม่ได้คัดลอกเลขหน้าอย่างครบถ้วน
6. เมื่อไฟล์จริงเปิดไม่ได้ โค้ดฐาน main มีการใช้ template ทดแทน ทำให้พิกัดของไฟล์ที่นิสิตส่งมาอาจถูกวาดบนแบบเปล่าที่ต่างกัน ส่วนการเลิกพฤติกรรมนี้อยู่ในชุด SIT ที่ยังไม่ deploy

## แนวทางแก้ที่ควรใช้

- ผูกตำแหน่งกับ **ไฟล์ต้นฉบับที่ลงนาม + รุ่นแบบฟอร์ม + หน้า + บทบาทใน workflow**
- ให้การแสดงตัวอย่าง การปรับตำแหน่ง และการดาวน์โหลดอ้างอิงไฟล์เดียวกัน
- คงพิกัดเฉพาะคำร้องที่ตรวจแล้วไว้ แยกค่ามาตรฐานของแต่ละแบบ ไม่แทนทุกฉบับด้วยค่าชุดเดียว
- ไม่ให้การคัดลอกตำแหน่งคัดลอกชื่อ วันที่ หรือหลักฐานอนุมัติจากอีกคำร้อง
- แบบที่ไม่รู้จักหรือไฟล์สแกนที่จัดหน้าใหม่ต้องตรวจภาพจริงก่อนใช้ค่าเริ่มต้น
- แพตช์ฟอนต์/สเกลหน้าวางตำแหน่งช่วยให้ภาพตรงกับ PDF แต่ไม่ได้แก้การเลือกช่องตามแบบฟอร์มทั้งหมด

## ขอบเขตที่ยังไม่ได้ตรวจ

ระบบอนุมัติอัตโนมัติปฏิเสธคำสั่งอ่านและดาวน์โหลดคำร้องจริงทั้งหมดจาก PRD เพราะเป็นการดึงข้อมูลส่วนบุคคลและลายเซ็นจำนวนมาก คำสั่งนั้นไม่ได้รัน การตรวจเอกสารจริงครบทุกคำร้องจึงยังต้องได้รับอนุญาตสำหรับขอบเขตข้อมูลนี้ก่อน ไม่มีการดึงข้อมูลครบชุดหรือเปลี่ยนข้อมูลแทนการตรวจ

หลักฐานแบบฟอร์มโดยละเอียดอยู่ที่ `tmp/audit/template-position-audit.md` และ `tmp/audit/template-inventory.json` ภายใน worktree นี้ เป็นข้อมูลจากแบบฟอร์มที่มีอยู่ในโปรเจกต์เท่านั้น
